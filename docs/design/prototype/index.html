01摘要

SUMMARY

我在合肥写前端与桌面应用，主力栈是 Electron + React + TypeScript，站点与工具链走 Astro 全静态。 偏好把状态与结论写下来：架构文档逐条标 file:line，回归用例串成一条命令，踩过的坑连根写进笔记。 现在做的事情是让用户的数据先落在自己机器上，云盘只当同步通道。

02核心能力

证据都在笔记里 →
01

桌面应用的落盘时序

主/渲染分层，回填完成前一律丢弃写库请求；写盘走 .tmp + 同卷 rename 原子替换。半截 JSON 不会被误判成「本机为空」推上云端。

↳ 证据 · 笔记《原子写与 ready 闸门》
02

按真机语义实现协议，而不是按文档常识

坚果云用 409 表示路径不存在，也不是 404。目录逐级 MKCOL，连接自检用 PROPFIND 定位缺在哪一层，提示里直接给出该层实际有哪些目录。

↳ 证据 · 笔记《坚果云用 409 表示路径不存在》
03

把「我以为的行为」变成「跑一次就知道的行为」

backup / stats / webdav / todo / persistence / config 六套回归串成一条命令，mock 服务验证协议语义，pre-commit 据此把关，不触碰真实账号。

↳ 证据 · 笔记《六套回归，串成一条命令》
04

内容工程：Markdown 即数据源

内容集合 + zod 校验 frontmatter，编译期解析 [[双链]] 生成反链与图谱节点，零运行时数据库、零第三方请求。

↳ 证据 · 本站源码与《知识花园需要链接》
