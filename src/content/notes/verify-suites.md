这个项目没有用测试框架。六套 `verify-*.mjs`，用 `node:assert` 直接跑，串成 `npm run verify`，挂在 pre-commit 上。

## 为什么不是一个测试框架

Electron 项目里最值钱的断言不在「组件渲染成什么样」，而在**纯函数与协议语义**：

- `planPull` 在两边时间戳相等时返回什么；
- WebDAV 服务端回 409 时 `pull` 走哪条分支；
- CSV 往返之后字段是否逐个相等；
- 快照回填后有没有残留旧数据。

这些不需要 DOM，不需要浏览器，只需要一个断言库。`node:assert` 加 `esbuild` 打包，启动时间几乎为零，跑完整套不到两秒——这是它能一直挂在前置钩子上的前提。

## 六套各自守住什么

| 套件 | 守的东西 | 典型用例 |
| --- | --- | --- |
| backup | 导出导入往返、归档分组 | CSV 公式前缀往返无损 |
| stats | 分母口径、区间边界 | 整季 92 天、未来区间返回 empty |
| webdav | 协议语义、冲突决策 | 409 归一为「云端为空」 |
| todo | 完成态与排序稳定性 | 勾选后行数与行高不变 |
| persistence | 落盘时序、快照回填 | ready 前写入被丢弃 |
| config | 凭据读写、路径归一化 | 空明文不抹掉已存密文 |

## mock 服务比真机更可靠

同步相关的用例全部打本地 mock：

```js
// mock 按真机行为实现：父目录不在就回 409，PROPFIND 回 207
if (!dirs.has(parentOf(path))) return res(409);
```

它比连真实坚果云好在三点：不消耗账号配额、不依赖网络、可以精确构造「半路失败」。代价是 mock 的语义必须来自**真实抓包**，否则就是自娱自乐——[[webdav-409]] 这条结论就是从 `curl -i` 里得来的。

## 断言要锁住「不要改回去」

有一类断言不测行为，测实现约束：

```js
// 防止有人把「测试连接」改回只读已保存的旧密码
assert.ok(source.includes('mergeConfigInput(readCfg(), input)'));
```

看起来粗暴，但它守的是一条真实的回归：改密码后不保存直接测连接，会一直 401。这种 bug 用行为测试很难覆盖（要模拟界面），用源码断言一行就够。

## 门禁必须默认生效

规则写在文档里，等于没有规则。`prepare` 生命周期里自动装钩子，`node_modules` 缺失时不放行——后者尤其重要，因为它是最容易「静默跳过校验」的一条路。

## 副产品

写这六套的过程本身就在暴露设计问题：凡是难测的地方，基本都是「判断与执行混在一起」。于是才有了 [[plan-pull-plan-push]] 这样的拆分。**测试写不下去，通常是设计在报警。**
