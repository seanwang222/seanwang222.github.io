导出 CSV 时如果直接把用户输入写进单元格，等于把「用户可控的字符串」交给 Excel 当公式执行。

## 触发条件

以 `=`、`+`、`-`、`@`、制表符、回车开头的单元格，Excel 与 WPS 会当作公式。一个待办事项叫 `=HYPERLINK("http://evil","点我")` 就足够。

```csv
标题,备注
买牛奶,=1+1
```

用 Excel 打开，第二列显示 `2`——公式已经执行了。真实攻击里这一格可以是 `=cmd|'/c calc'!A0`（DDE），也可以是外部数据拉取。

## 挡法：前置撇号，导入时脱掉

```js
function csvCell(value) {
  const s = String(value ?? '');
  const risky = /^[=+\-@\t\r]/.test(s);
  return risky ? `'${s}` : s;
}

function parseCell(raw) {
  return raw.startsWith("'") ? raw.slice(1) : raw;
}
```

关键在于这两步必须**成对**。只加不脱，导出再导入一次，所有以这些字符开头的内容都会永久多出一个撇号——每轮备份加一个，几轮之后数据就毁了。

## 往返无损才是验收标准

判断这类护栏写对没有，只看一件事：

```
导出 → 导入 → 与原始数据逐字段比较
```

不是「看起来对」，是逐字段相等。这条断言后来成了 [[verify-suites]] 里 backup 套件的一个固定用例。

## 边界：哪些字符真的危险

| 前缀 | 危险 | 说明 |
| --- | --- | --- |
| `=` | 是 | 公式 |
| `+` `-` | 是 | Excel 会尝试解析为公式/数值 |
| `@` | 是 | 旧版 Excel 的函数调用 |
| `\t` `\r` | 是 | 可绕过前缀检查 |
| 空格开头 | 否 | 但空格 + `=` 需要 trim 后判断 |

最后一行是容易漏的：`" =1+1"` 前面带一个空格，严格前缀匹配不触发，但 Excel 打开时可能仍会解析。稳妥做法是先 `trimStart()` 判断，再决定是否加撇号。

同类思路：任何「用户数据进了解释器」的地方都要问一遍——Shell、SQL、HTML、正则、CSV。这也是 [[local-first]] 里那条「数据在自己手里」的阴暗面：文件越容易被别的软件打开，越要防这些。
